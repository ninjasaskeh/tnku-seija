# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

@AGENTS.md

Next.js here is 16.4 (React 19.3, Tailwind 4.3). APIs differ from training data — read `node_modules/next/dist/docs/` before using a Next API. `next.config.ts` enables `cacheComponents` and `partialPrefetching`, and Tailwind runs through a Turbopack CSS loader rule (`@tailwindcss/turbopack`), not PostCSS.

## Commands

- `npm run dev` — dev server on http://localhost:3000
- `npm run build` / `npm start` — production build / serve
- `npm run lint` — ESLint (flat config, `eslint-config-next` core-web-vitals + typescript)
- `npx tsc --noEmit` — type check (no separate script)
- `npm run preview:single` — Vite build of the same page into one self-contained `preview-dist/index.html` (all JS/CSS/fonts inlined)
- `npm run db:migrate` — `prisma migrate dev` (create/apply migrations); `npm run db:deploy` applies them in production
- `npm run db:seed` — fill the DB from `src/data` (idempotent: profile upsert, skills/projects only if empty)
- `npm run db:generate` — regenerate the Prisma client into `src/generated/prisma` (gitignored; also runs on `postinstall`)
- `npx next typegen` — regenerate route types (`PageProps<"/route">`, `LayoutProps`) after adding routes without the dev server running

Env vars are documented in `.env.example` (`DATABASE_URL`, `ANTHROPIC_API_KEY`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `ADMIN_EMAILS`, `AWS_*` + `STORAGE_BUCKET`, `IP_SALT`, optional `CHAT_MODEL` and `CHAT_LIMIT_*`). The Prisma CLI loads `.env` via `dotenv` in `prisma.config.ts`.

No test suite exists. `README.md` is unedited create-next-app boilerplate (mentions `next/font`/Geist and `app/page.tsx`); ignore it.

## Architecture

Full-stack Next.js app. The public site is a single page (`src/app/page.tsx` → `components/Home.tsx`) with a full-screen 3D voxel "stage" behind seven scroll "chapters". Concept is **Round Trip**: the visitor is an HTTP request travelling the stack, so each chapter is a "hop" — hero = Request (`GET /you`), about = Handshake (SYN/SYN-ACK/ACK + certificate), projects = Routes (each project is an endpoint with a JSON response), logs = Logs (work history as `access.log` lines: current job `200 OK`, past jobs `301 Moved`, kind shown as an HTTP method, native `<details>`, all open by default), skills = Query (filterable `SELECT ... FROM skills` table), keepalive = Keep-Alive (`Connection: keep-alive`: the owner's journey, `profile.story` paragraphs rendered as numbered "beats"), contact = Response (`200 OK`, contact info as response headers). Keep new copy and graphics inside that metaphor. `/styleguide` is a separate design-token reference page. Code comments and data-file comments are in Indonesian; site copy is English.

**Stage state is a plain mutable module, not React state.** `src/lib/stage.ts` holds a `stage` object (current chapter, target shape id, project index, dark/light colors, pose, `glitch` 0..1 spiked on chapter change and decayed in the scene) plus `CHAPTERS` config (also per-hop `label`, `layer`, `addr`, `ms` used by headings, header URL bar, `TraceHud`, `CircuitTrace`, `TabPresence`, and the terminal's `traceroute`). `setChapter()` tweens colors/pose with GSAP and writes CSS vars `--stage-dark`, `--stage-light`, `--stage-fg` on `<html>`. The R3F scene reads `stage` every frame in `useFrame`; it never re-renders from it. `src/lib/pointer.ts` is the same pattern for mouse data (shared by cursor, hero, and scene). Keep this pattern — do not move per-frame data into React state.

**Adding a hop** means touching every list keyed by chapter: `ChapterId`/`CHAPTERS`/`CHAPTER_ORDER` in `stage.ts`, a voxel generator, `TITLES` in `TabPresence.tsx`, the hard-coded list in `src/app/api/track/route.ts`, `HOP_ORDER`/`HOP_LABEL` in `src/lib/stats.ts`, `nav` in `src/data/profile.ts`, and the static favicons (one square per hop). Hop counts in copy come from `CHAPTER_ORDER.length`.

**Chapter switching flow:** each section root has `data-chapter="<ChapterId>"`. `StageDirector` creates a ScrollTrigger per `[data-chapter]` element and calls `setChapter()` when it crosses 60% of the viewport. To change a chapter's shape, colors, or object position, edit `CHAPTERS` in `src/lib/stage.ts`. The projects chapter uses shape `route<index>` (voxels spell `/01`, `/02`…); `Projects.tsx` calls `setProject()` as the active slide changes. In staged (rail) mode a slide change runs one GSAP timeline: old and new slides are clipped with `steps(10)` along one shared moving edge (a scan line carrying a `→ /0N` tag, direction follows scroll direction), `[data-px]` children slide with parallax (factor = attribute value), `[data-status]` is scrambled back to `200 OK`, and `[data-scan]` (thumbnail) opens top-down; all inline styles are cleared on complete or when interrupted, so inactive slides go back to `invisible`. A thin bar on the route index follows overall scroll progress continuously. Section headings come from `HopHeading` (`components/layout/Hop.tsx`); its meta line is a `[data-node]`.

**Page-level concept pieces (all in `components/fx/`):**
- **Real network data:** `src/lib/net.ts` measures real RTT with `HEAD` fetches to the page (`startNet()` in `SmoothScroll`, `ping()` from the terminal and `PingField` clicks). Returns `null` on `file:` (preview build), so UI must show a fallback. Read it with `Rtt` from `NetStatus.tsx`. Decorative numbers (`CHAPTERS[*].ms`, `addr`, project latency) are still fake.
- **`Reassemble`** replaces scramble on big headings: each char is a numbered "packet" that arrives out of order, one is dropped and retransmitted. Styling is the `.pkt` class in `globals.css` driven by CSS vars `--pk`/`--rt`. Its wrapper is `overflow-x-clip` so flying chars never widen the page on mobile — keep that.
- **`CircuitTrace`** draws one PCB-style SVG trace through every `[data-node]` (left gutter) and a mid-section via on the right, inside `<main className="relative">`; a lit packet follows the viewport center each GSAP tick. Geometry rebuilds on `ResizeObserver`.
- **`TabPresence`** rewrites `document.title` and draws the favicon per hop; **`PingField`** turns clicks on empty space into a real ping with a pixel ring.
- **Calm mode** (`src/lib/calm.ts`, toggle button in `SiteHeader`, saved in `localStorage` key `portfolio:calm`, sets `html.calm`): hides `CircuitTrace` and `TraceHud` (`in-[.calm]:hidden`), stops the voxel packet stream and shader glitch, skips `Reassemble` and `PingField`. New busy effects should respect it. The shader glitch follows mouse speed at full strength (the owner wants it) plus a spike on chapter change; calm mode turns it off.

**3D scene (`src/components/three/`):**
- `Stage.tsx` picks mode: `full` (desktop, 4096 cubes + custom dither post-process), `lite` (≤1023px or coarse pointer, 1400 cubes, no post-processing, CSS scanlines), or `off` (reduced motion or no WebGL). Loads `StageScene` via `next/dynamic` with `ssr: false` inside an error boundary.
- `VoxelSystem.ts` animates one `InstancedMesh` on the CPU between formations. Shape ids map to generators in `points()`: `cube`, `packet` (envelope), `lock`, `log` (hollow terminal window with log lines), `db` (stacked discs), `heart` (Keep-Alive), `ok` ("200"), `routeN`. Text shapes are rasterized from a 2D canvas; others use `fit()` to shrink resolution until they fit the cube budget. The last 5% of instances never join a shape: they are the "packet stream" falling in two lanes behind the object (faster while `stage.glitch` is high). Transitions funnel cubes through a narrow column top-first. A new shape needs a generator there, a `CHAPTERS` entry, and a rotation case in `StageScene.tsx`'s `Rig`.
- `quietThree.ts` (imported first in `StageScene.tsx`) uses `THREE.setConsoleFunction` to drop only the "THREE.Clock … deprecated" warning that R3F 9.x triggers internally; delete it once R3F uses `THREE.Timer`.
- `DitherEffect.ts` is a custom `postprocessing` Effect (1-bit dither + row glitch + "packet loss" block inversion) fed `stage.light`/`stage.dark` each frame.

**`TraceHud`** is only the bottom-right waterfall (layer + ms) and a mobile progress line.

**Header nav:** `SiteHeader` shows `DesktopNav` (`components/layout/DesktopNav.tsx`) at `lg+`: passed hops in full color, upcoming hops `text-dim`, the active link gets `aria-current` plus a "packet" bar underneath that GSAP moves with `steps(6)` (instant in calm mode / reduced motion, hidden on the hero hop, re-placed on `ResizeObserver`), and hover/focus shows a decorative tooltip with the hop's `layer · addr · ms`; link widths never change between states so nothing shifts; below that a "Menu" button opens `MobileNav` (`components/layout/MobileNav.tsx`), a bottom drawer built on shadcn's Drawer (`src/components/ui/drawer.tsx`, `vaul`; added by hand since there is no `components.json`, restyled to the stage vars, `z-[70]` so it sits above the chat button). `cn` in `src/lib/utils.ts` only joins classes (no tailwind-merge, which would mis-merge custom tokens like `text-micro` vs `text-accent`). Keep `noBodyStyles` on the Drawer: without it vaul sets `body { position: fixed }` on Safari/iOS, `scrollY` drops to 0 and ScrollTrigger jumps the stage to the hero hop behind the drawer. While open, Lenis is stopped; a link click closes the drawer, restarts Lenis, waits two frames, calls `lenis.resize()` and then `scrollTo(href, { offset: -56 })`. `PingField` ignores clicks inside `[data-vaul-drawer]`/`[data-vaul-overlay]`.

**Boot sequence:** `BootScreen` waits for fonts (max 700ms), runs a `curl`-style connect log with a percent counter and block progress bar, then sweeps the screen away as a diagonal wave of outlined cells, once per tab session (`sessionStorage` key `portfolio:booted`). `markBooted()` fires at the START of that wave (not at the end), setting `html[data-booted]` and dispatching `boot:done`, so hero text assembles while the overlay leaves. Until then `globals.css` hides `#top [data-in]` and `[data-reasm="boot"]` chars (visible again under reduced motion and in `<noscript>`), so nothing shows fully and then re-animates. An inline script in `layout.tsx` `<head>` (and `preview/index.html`) adds `html.boot-seen` before paint for returning visitors so the server-rendered overlay never flashes; keep the key in sync in all three places. Log lines start `invisible` in the markup for the same reason. `StageDirector` sets the hero chapter on mount (before boot ends) so the voxels have already formed when the overlay leaves; `useBooted()` (`src/lib/boot.ts`) gates hero text animations and scroll-driven chapter switching; `SmoothScroll` keeps Lenis stopped while `html.is-booting`.

**Section / Fx split:** `components/sections/X.tsx` is a server component with markup; `XFx.tsx` is a `"use client"` component that renders `null` and only runs GSAP on that section (targets elements via selectors such as `#top [data-in]`).

**GSAP:** always import from `@/lib/gsap`, which registers plugins (ScrollTrigger, SplitText, ScrambleText, Draggable, Inertia) and exports shared media queries `MOTION_OK`, `FINE_POINTER`, `RAIL`. Wrap animations in `gsap.matchMedia()` with `MOTION_OK` so reduced motion gets no animation. Lenis smooth scroll is driven by the GSAP ticker; the global instance is `lenisRef` (`src/lib/lenis.ts`) — use `lenisRef.current?.scrollTo()` for programmatic scroll.

**Styling:** all tokens live in `@theme` in `src/app/globals.css` (palette `acid/ink/paper/volt/violet/ash/line`, fluid type scale `text-micro`…`text-mega`, fonts Archivo Variable + Space Mono via `@fontsource`). Custom variants: `rail:` (wide+tall+motion OK; Projects becomes a horizontal rail) and `fine:` (mouse). Utilities such as `panel`, `text-accent`, `bg-accent`, `method` (HTTP method badge) follow the stage CSS vars, so chapter colors propagate automatically — prefer them over fixed palette colors for content that sits on the stage. `wire-x`/`wire-y`/`wire-flow` draw dashed "cables" in `currentColor`; `caret` is a blinking terminal block.

**Content comes from PostgreSQL, not the data files.** Prisma 7 (`prisma/schema.prisma`, generator `prisma-client` → `src/generated/prisma`, driver adapter `@prisma/adapter-pg`; client singleton `db()` in `src/lib/db.ts`). `getContent()` (`src/lib/content.ts`) is a `"use cache"` function tagged `CONTENT_TAG` with `cacheLife("days")`, so the home page and `generateMetadata` stay in the static shell; admin Server Actions call `updateTag(CONTENT_TAG)` after every write. If the DB is unreachable or has no `Profile` row it returns `defaultContent` from `src/data` (which is also the seed source and what the preview build renders). Content shape is `src/lib/content-types.ts` (plain types, safe anywhere). `page.tsx` passes it to `<Home content>`, which wraps everything in `ContentProvider`: client components read it with `useContent()`, server section components (`Hero`, `About`, `Skills`, `Contact`) get it as props. Never import `@/data/*` into components for content (only `nav` stays static in `src/data/profile.ts`). Project order sets the /01, /02… routes the voxels form; `skills` group names become the layer filters in `SkillQuery`; `experience` order is the access.log order (newest first). The `Experience` query in `getContent()` has its own `.catch(() => [])`, so a missing table (migration not applied) only empties the Logs hop instead of dropping the whole page to `defaultContent`.

**AI terminal:** the conversation state lives in `components/chat/ChatProvider.tsx` (wrapped around the page in `Home.tsx`), so the inline terminal in the Handshake section and the floating `ChatLauncher` panel (bottom-right button, colored with `bg-accent` so it follows the hop; hidden during boot and while the inline terminal is on screen; Esc closes, focus returns to the button) show one shared chat. On phones the panel is a bottom sheet (backdrop tap closes, button hidden while open, input not auto-focused) whose `bottom`/height come from CSS vars `--kb`/`--vvh` that `ChatLauncher` writes from `window.visualViewport`, so it always sits right above the virtual keyboard; the input is 16px on mobile to stop iOS zoom. `Terminal.tsx` is only the view: `variant="inline"` has the command/question chips; `variant="panel"` is a plain chat (no chips, no footer). The `TraceHud` waterfall sits above the floating button (`bottom-24`), never beside it. The provider answers built-in commands locally and sends any other input to `POST /api/chat` (`src/app/api/chat/route.ts`), streaming plain text back; the session id comes back in `x-chat-session` and is kept in `sessionStorage` (`portfolio:chat`). The route uses the official `@anthropic-ai/sdk` (`client.beta.messages.stream`) with `CHAT_MODEL` (default `claude-haiku-5-5`), `output_config.effort: "low"`, `max_tokens: MAX_OUTPUT_TOKENS` (1024; Haiku 5.5 thinks adaptively and thinking counts toward it), server-side refusal fallbacks only for models where `supportsFallback()` is true (Haiku has none), and a cached system prompt (`systemPrompt()`) that asks for answers of about 60 words max: replies in the language and register of the visitor's latest message (Indonesian slang → "gue/lu", polite Indonesian → "aku/kamu", English → casual English), facts about the owner only from site data (never invented, preferences included), email only when contact/hiring comes up, no visible reasoning (the prompt has a few style-only example exchanges), casual off-topic small talk answered briefly with at most one light, harmless meme reference, and any work-type request (writing/fixing code, homework, long or multi-step tasks) declined playfully with a pointer to the email built from the content by `systemPrompt()` in `src/lib/chat.ts`. History is loaded from the DB, never from the client; failed answers (`stopReason: "error"`) are excluded. Rate limits (`checkLimits`) count `ChatMessage` rows: global per day, per hashed IP per 10 min and per day, per session. Without `ANTHROPIC_API_KEY` the route returns 503 and the terminal says the AI is offline. IP hashing (`src/lib/request.ts`) trusts the first `x-forwarded-for` entry, which is only trustworthy behind a proxy that overwrites it (e.g. Vercel).

**Easter eggs (AI "people" lore):** the `Reference` model (`kind` public/friend/other, `names` incl. nicknames, `note`, `enabled`) is edited at `/admin/easter-eggs` and loaded by `getReferences()` (`src/lib/references.ts`, `"use cache"` with the same `CONTENT_TAG`, so saving refreshes the chat prompt). `systemPrompt(content, references)` appends a `<people>` block: notes override the model's own knowledge; public figures get no political opinions/insults; friends only what the note says. Not shown on the public page.

**Analytics:** `components/fx/Analytics.tsx` sends one `view` per tab and one `hop` per chapter (first time) to `POST /api/track` via `sendBeacon`; anonymous random `visitId` in `sessionStorage`, no cookies, no IP, skipped under Do Not Track / GPC. Stored in `PageEvent`.

**Admin (`/admin`):** login is self-hosted **Better Auth** (`better-auth`), Google only. Per the Better Auth docs the config lives in `src/lib/auth.ts` (`export const auth = betterAuth({...})` with `prismaAdapter(db(), { provider: "postgresql" })`, `socialProviders.google`, and `nextCookies()` as the last plugin so Server Actions can set cookies); `src/lib/auth-client.ts` is `createAuthClient()` from `better-auth/react`; `src/app/api/auth/[...all]/route.ts` is `toNextJsHandler(auth)`. Tables `user`/`session`/`account`/`verification` are Prisma models (`User`, `Session`, `Account`, `Verification`) matching better-auth's core schema; check them after upgrades with `npx auth@latest check schema`. Env: `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL` (base URL; Google redirect URI is `<BETTER_AUTH_URL>/api/auth/callback/google`), `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `ADMIN_EMAILS`. Sign-up is closed in config: a `databaseHooks.user.create.before` hook throws `APIError("FORBIDDEN", { code: "not_admin" })` for emails not in `ADMIN_EMAILS`, which Better Auth turns into a redirect to `/admin/login?error=not_admin`. Session helpers are in `src/lib/session.ts`: `getViewer()` (`auth.api.getSession({ headers: await headers() })` after `connection()`) and `requireAdmin()` (also requires `emailVerified`). Pages read the session inside `<Suspense>` (required with Cache Components; don't use `export const dynamic`), and every Server Action in `src/app/admin/actions.ts` calls `requireAdmin()` itself and validates input (`safeUrl` rejects non-http(s)/mailto links). `src/proxy.ts` (matcher `/admin/:path*`, skips `/admin/login`) redirects to `/admin/login` when there is no Better Auth session cookie (`getSessionCookie`), so signed-out visitors never see the prerendered admin shell; it is only an optimistic check, the real authorization stays in `requireAdmin()`. Project thumbnails upload through the `saveProject` action to **Neon Object Storage** (`src/lib/storage.ts`, `@aws-sdk/client-s3`, env `AWS_*` + `STORAGE_BUCKET`; the bucket must be `public_read`, and stored values are full public URLs; replaced/deleted images are removed from the bucket). Max 4 MB, which is why `next.config.ts` sets `experimental.serverActions.bodySizeLimit: "5mb"`. Dashboard stats are in `src/lib/stats.ts` (raw SQL via `$queryRaw`; AI cost is an estimate per stored model from the `PRICES` table in `src/lib/chat.ts` — add a row when using a new `CHAT_MODEL`). Admin UI ("NOC") has no stage/GSAP and may use `next/link`, unlike the home page. Pages live in the route group `src/app/admin/(panel)/` (Overview `/admin` with `?range=7|30|90`, `/admin/conversations[/id]`, `/admin/profile`, `/admin/story` (Keep-Alive beats, saved by `saveStory`; `saveProfile` must not touch `story`), `/admin/skills`, `/admin/projects[/id|new]`, `/admin/experience` (all entries saved at once by `saveExperience`, which zips `form.getAll()` columns by index, so the editor has no checkboxes: empty End = current job), `/admin/easter-eggs`), sharing `(panel)/layout.tsx` (sidebar + session/status footer in `<Suspense>`); `/admin/login` sits outside the group. Old `/admin/content` and `/admin/chats/:id` redirect in `next.config.ts`. Building blocks are in `src/components/admin/` (no shadcn: `ui.tsx` primitives + `btn()`, `charts.tsx`, `StatTile`, `skeletons.tsx`; `Select.tsx` wraps react-select in `unstyled` mode with theme classes: `SelectField` and `TagField` (creatable tags), both post through a hidden input via `name`, tags joined by `,`; `Toaster.tsx` is shadcn's sonner wrapper restyled for the NOC look, mounted once in `src/app/admin/layout.tsx`). Action results show as toasts: `ActionForm` toasts the returned `ok`/`error`; actions that `redirect()` call `flash(message)` first, which sets the short-lived `admin-toast` cookie (`FLASH_COOKIE` in `src/lib/flash.ts`) that `FlashToast` reads and clears on the next page. Every data read goes inside `<Suspense>` with a layout-shaped skeleton from `skeletons.tsx`, never a text fallback; `usePathname()` must also sit inside `<Suspense>` (see `Sidebar.tsx`). Charts follow the dataviz rules: single series so no legend, bars ≤24px with 4px rounded data end, hairline grid, text in text colors (values never acid), per-bar hover + arrow-key tooltip, and an sr-only data table.

`data-cursor="LABEL"` on any element makes the custom cursor show that label on hover.

## Single-file preview build

`vite.preview.config.mts` builds `preview/main.tsx`, which renders `<Home content={defaultContent} />` (`src/components/Home.tsx` with the static `src/data` content) directly with React DOM — no server, no DB; `/api/*` calls fail there, so the terminal AI, ping, and analytics degrade gracefully. It aliases `next/dynamic` to `preview/next-dynamic.tsx` (`React.lazy` shim), and `preview/preview.css` imports `globals.css` with `@source "../src"`. Code reachable from `Home.tsx` must therefore not depend on Next-only or server-only modules (`next/cache`, `next/headers`, `@/lib/db`, `@/lib/content`) or Next runtime APIs beyond `next/dynamic`; adding one (e.g. `next/image`, `next/link`, server-only APIs) requires a matching shim/alias in the preview config.
